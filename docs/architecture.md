# アーキテクチャ設計

このドキュメントはリポジトリの構成と技術選定の意図を記録したものです。

---

## 全体構成

```
インターネット（ユーザー）
    ↓ HTTPS / UDP
VPS（ConoHa）
    Nginx：HTTP/HTTPS のリバースプロキシ
    iptables / Nginx stream：UDP ゲームサーバのリレー
    ↓ Tailscale（プライベートネットワーク）
自宅サーバ（Ubuntu 26.04 LTS）
    Docker Compose：各サービスをコンテナで管理
    ↓ Tailscale
自宅 PC
    ローカル AI（Ollama 等）
    Ansible 実行元
```

---

## 技術選定の理由

### Tailscale

自宅サーバはルーター内側にあるため、そのままでは外部から接続できません。
選択肢として SSH リバーストンネルや VPN（WireGuard）もありましたが、Tailscale を選んだ理由は以下の通りです。

- セットアップが簡単（認証キー1つで参加できる）
- ノード間の接続が自動で管理される（IP アドレスが固定される）
- タブレット・スマートフォンにもアプリが提供されており、外出先からの接続が容易
- WireGuard ベースのため通信は暗号化済み

### Docker Compose（サービスごとにファイルを分割）

全サービスを1ファイルにまとめる方法もありますが、ファイルを分割した理由は以下の通りです。

- 使いたいサービスだけを選んで起動できる（他者が環境を再現しやすい）
- サービスごとに独立しているため、1つのサービスの設定変更が他に影響しない
- 将来サービスを追加・削除しやすい

### Ansible

サーバの構成管理に Ansible を選んだ理由は以下の通りです。

- エージェントレス（自宅サーバ側に特別なソフトが不要、SSH が通れば動く）
- YAML で設定を記述するため、何をしているかが読みやすい
- 冪等性（何度実行しても同じ結果になる）があるため、復旧時に安心して実行できる

### VPS をリバースプロキシ専用にした理由

自宅サーバに直接グローバル IP を持たせる方法もありますが、以下の理由で VPS を経由しています。

- 自宅の回線・IP アドレスを直接公開しないため、セキュリティリスクを下げられる
- 自宅サーバの電源を落としても VPS は生きているため、メンテナンスがしやすい
- 将来 Cloudflare Tunnel に移行する場合も、Nginx 設定をサービス側に寄せてあるため移行コストが低い

### UFW のロックダウン設計

`02_tailscale` 完了後は SSH を含む全ポートを Tailscale 経由のみに制限しています。
これにより、Tailscale の認証を突破しない限りサーバに触れない状態になります。
自宅サーバは個人用途のため、この割り切りが運用のシンプルさとセキュリティのバランスとして適切と判断しました。

## ディレクトリ構成の方針

手順番号でフォルダを切っており、番号順に実行すれば環境が再現できる設計にしています。

| フォルダ | 内容 |
|---|---|
| `01_initial_setup` | OS 設定・SSH・UFW 基本設定 |
| `02_tailscale` | Tailscale 導入・UFW ロックダウン |
| `03_docker` | Docker 導入 |
| `04_services` | 各サービスの Docker Compose |
| `05_vps` | VPS の Nginx・UFW 設定 |
| `06_backup` | バックアップ設計・スクリプト |

復旧時は `01` から順番に Ansible を実行し、`04_services` で `make up-core` を実行するだけで環境が戻ります。

## 今後の予定

### Cloudflare Tunnel への移行

HTTP/HTTPS サービスは将来 Cloudflare Tunnel に移行する予定です。
Cloudflare Tunnel は VPS なしで外部公開できるため、VPS のコストを削減できます。
UDP ゲームサーバは Cloudflare Tunnel では通せないため、VPS は引き続き使用します。

### サービスの追加予定

| サービス | 用途 |
|---|---|
| Bluesky PDS | 分散型 SNS（AT Protocol） |
| PeerTube | 動画配信 |
| River | フィードリーダー |
| Bluecast | （用途検討中） |

各サービスは `04_services/compose/` にファイルを追加するだけで対応できます。
